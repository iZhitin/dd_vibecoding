# Отчет по задаче UI-001: Создать Layout и систему роутинга с auth-guard

## Контекст
Был проинициализирован базовый frontend (React + Vite + Tailwind + Zustand). Потребовалось добавить систему управления состоянием авторизации и реализовать защиту маршрутов от неавторизованного доступа.

## Что было сделано
1. **Zustand store (authStore)**: Создан `frontend/src/stores/authStore.ts` с персистентным хранением стейта (токена) в `localStorage`, а также функциями для `login` и `logout`.
2. **API Client**: Создан легковесный HTTP-клиент поверх стандартного `fetch` в `frontend/src/api/client.ts`. Он:
    - Автоматически пробрасывает заголовок `Authorization: Bearer <token>`.
    - Устанавливает `Content-Type: application/json` по умолчанию.
    - Перехватывает код `401 Unauthorized` API: выполняет `logout` и кидает разработчика на `/login`.
3. **Обёртки маршрутизатора (Guards)**: 
    - `AuthGuard` для защиты приватных страниц (редиректит на `/login` при отсутствии токена).
    - `GuestGuard` для сокрытия публичной страницы авторизации (редиректит на `/capture`, если пользователь уже залогинен).
4. **Layout**: Создан минималистичный макет приложения `frontend/src/components/Layout.tsx` с заголовком, блоком отображения стриков и навигационным меню.
5. **App Router**: Обновлен `App.tsx` для использования созданных гвардов и макета (с учетом сохранения существующего роутинга для `ReviewPage`).

## Вывод / Решения для ADR
- Вместо добавления тяжеловесной зависимости `axios` для реализации интерцепторов запросов, я написал компактную обёртку вокруг встроенного `fetch`, что соответствует принципам KISS и Clean Code. Это решение позволяет избежать замусоривания `package.json`.

## Статус
Все 4 Критерия готовности (DoD) выполнены. Код успешно компилируется (`tsc -b && vite build`) без ошибок типизации.
