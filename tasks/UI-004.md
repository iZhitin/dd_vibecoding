# Отчет о задаче [UI-004]

## Описание
Создана страница Practice (Zen Mode) для прохождения ежедневной 10-словной практики.

## Что сделано:
- **`frontend/src/api/practice.ts`**: Создан HTTP-клиент (fetch API) для эндпоинтов `/api/practice/daily` и `/api/practice/submit`.
- **`frontend/src/api/cards.ts`**: Добавлен клиентский метод для обращения к эндпоинту `/api/cards/{id}/translation`.
- **`frontend/src/stores/practiceStore.ts`**: Назначен Zustand store для управления загрузкой и состоянием сессии (набор карточек, текущий индекс, пользовательские тексты, состояние отправки).
- **`frontend/src/components/PracticeCard.tsx`**: Создан компонент для отображения отдельной карточки-вопроса в Zen Mode стиле с `autoFocus` инпутом, контекстом предыдущего ввода, кнопкой Reveal с эффектами и `framer-motion` анимациями (слайд перехода).
- **`frontend/src/pages/PracticePage.tsx`**: Настроены загрузка сессии через Zustand, подгрузка карточек (по `PracticeCard`) с помощью ключей (key re-mounting) в пределах `AnimatePresence`. Также реализован финальный экран с успехом сессии и возможностью возврата к Capture.

## Тестирование
- Запущены `npm run lint` и `npm run build` — оба завершились с успехом без ошибок.
- На клиенте корректно отрабатывают все переходы состояния (пусто, ошибка, успех загрузки списка, отображение по одной карточке через `PracticeCard`).

## ADR
В рамках этой задачи не потребовалось создавать новых ADR (архитектурных решений), так как PWA, API client и структура на основе `framer-motion` уже были заложены в предыдущих `[UI]` эпохах и `TECHSPEC.md`. Мы только переиспользовали их, в том числе заменили избыточный `useEffect` на `key`-перемонтирование для `PracticeCard` для получения более "чистого" React-подхода и избежания проблемы cascade renderings.
