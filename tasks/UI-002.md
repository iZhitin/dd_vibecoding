# Отчет по задаче UI-002: Создать страницу логина (Magic Link)

## Контекст
Был реализован Auth API для авторизации через Magic Link. Необходимо создать страницу логина, на которой пользователь сможет ввести свой email и получить письмо с ссылкой для входа, а также страницу верификации полученного токена.

## Что было сделано
1. **API Client (authApi)**: Создан `frontend/src/api/auth.ts` с методами `requestMagicLink` и `verifyToken`, использующими базовый `apiClient`.
2. **Страница LoginPage**: Реализован компонент `frontend/src/pages/LoginPage.tsx` с двумя состояниями:
    - Ввод email и кнопка "Send Magic Link".
    - Экран подтверждения отправки (Check your email).
    - Обработка состояний загрузки (isLoading) и ошибок интерфейса.
3. **Страница AuthVerifyPage**: Создан компонент `frontend/src/pages/AuthVerifyPage.tsx` для:
    - Парсинга `token` из query-параметров (`?token=...`).
    - Отправки `POST /api/auth/verify`.
    - Сохранения полученного JWT токена в `authStore`.
    - Редиректа на защищенный маршрут `/capture` при успешной верификации.
    - Отображения ошибок при просроченном/невалидном токене.
4. **App Router**: Внесен маршрут `/auth/verify` в `frontend/src/App.tsx` (внутри `GuestGuard`).
5. **Линтинг и форматирование**: Исправлены ошибки использования `useEffect` в `AuthVerifyPage` и строгие проверки типов в обработчиках ошибок `try/catch`. 

## Вывод / Решения для ADR
- Использована микрозадача (`queueMicrotask`) для предотвращения синхронного вызова функции обновления состояния (`setError`) внутри body `useEffect`, что удовлетворяет strict rules React 18.
- Не потребовалось писать новые ADR, так как реализация строго соответствовала PRD и TECHSPEC (Anti-Gamification дизайн, минимализм форм).

## Статус
Задача переведена в статус "выполненной" (закрыты все DoD). Код проверен линтером и форматером.
