# ADR 005: Использование structlog для структурированного логирования

## Контекст
В рамках задачи `[OPS]-[001]` нам потребовалось настроить структурированные логи (JSON) для парсинга и анализа. Uvicorn и FastAPI по умолчанию используют стандартный модуль `logging` без поддержки структурированного формата или удобного проброса параметров, таких как `request_id`.

## Решение
Внедрен пакет `structlog` для замены стандартного логгера.
- Настроен `structlog.stdlib.ProcessorFormatter` для перехвата стандартных логов (`uvicorn`, `fastapi`, `arq`).
- Обработчики `logging` заменены на консольный цветной или JSON формат в зависимости от `APP_ENV`.
- Добавлен middleware `logging_middleware`, который генерирует уникальный `request_id` (UUID) для каждого запроса и привязывает его к логам через `structlog.contextvars.bind_contextvars`. Это решает проблемы трассировки логов для конкретного запроса в отрыве от общей массы событий.

## Последствия
- **Положительные:** Все логи унифицированы под один формат. Появилась возможность трассировки запросов по `request_id`. Удобный разбор с помощью JSON в CI/CD и production окружениях.
- **Отрицательные:** Дополнительная зависимость `structlog`. Небольшая просадка производительности из-за накладных расходов на обработку `contextvars` и парсинг логов.
