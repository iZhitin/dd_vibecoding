# ADR: Использование встроенного fetch вместо axios для frontend API-клиента

**Дата:** 25 февраля 2026 г.
**Статус:** Принято

## Контекст
В задаче `UI-001` требовалась реализация HTTP-клиента с интерцепторами запросов (автодобавление `Bearer` токена и обработка ответов `401 Unauthorized` для запуска logout-лога). Изначально в обсуждении/backlog'e упоминалось использование `axios` или `fetch`.

## Решение
Разработать легковесную обёртку вокруг встроенного в браузер Web API `fetch` вместо добавления зависимости от библиотеки `axios`.

## Обоснование
1. **KISS и Clean Code:** Заимствование `axios` для всего двух интерцепторов (токен в заголовки и общая обработка `401`) — это overkill в реалиях React 18 / Vite.
2. Проектная директива (DRY) поощряет минимизацию размеров бандла (менее больше). 
3. Написанная обёртка `apiClient` решает все необходимые потребности API (перехват статусов, выброс типизированных ошибок, парсинг JSON ответов) всего в 40 строках кода.

## Последствия
- Плюсы: Уменьшен размер frontend bundle, нет сторонних зависимостей для простой сетевой работы.
- Минусы: Отсутствие встроенного механизма отмены запросов (CancelTokens) из коробки (при необходимости можно реализовать с помощью `AbortController`). Обновление кода API-клиента ложится на плечи команды (хотя функционал уже полностью покрывает нужды CRUD-эндпоинтов приложения).
