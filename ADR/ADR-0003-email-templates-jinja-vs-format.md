# ADR-0003: Использование Python format вместо Jinja2 для email-шаблонов

**Статус:** Принято  
**Дата:** 25 февраля 2026 г.

## Контекст и проблема
Для реализации задачи `[NOTIFY]-[002]` потребовалось создать HTML-шаблоны для отправки email сообщений (Magic Link, Reminder, Daily Digest) в минималистичном, монохромном стиле (согласно PRD §1: Anti-Gamification). Было необходимо выбрать инструмент для шаблонизации.

## Рассмотренные варианты
1. **Jinja2** — мощный и популярный шаблонизатор.
   - *Плюсы:* Изоляция HTML от Python-кода, богатая функциональность (циклы, условия, фильтры).
   - *Минусы:* Требует добавления новой зависимости в `pyproject.toml`, усложняет сборку и увеличивает размер среды. Дополнительные накладные расходы на I/O (чтение файлов).
2. **Python `str.format()`** и константы.
   - *Плюсы:* Нет новых зависимостей (out-of-the-box), высокая скорость работы, простота внедрения для простых и средних шаблонов. Идеально ложится в парадигму KISS, учитывая малый объём писем.
   - *Минусы:* Сложнее поддерживать очень большие шаблоны (менее наглядный код).

## Решение
Выбран вариант №2: использование встроенного механизма конкатенации/форматирования `str.format()` с описанием HTML в виде констант (многострочных строк) в отдельном файле `backend/app/templates/emails.py`. 

## Последствия
- Мы избежали добавления зависимости `jinja2`.
- Шаблоны оформлены в виде строковых констант.
- При последующем усложнении писем может потребоваться переход на Jinja2, однако для текущих требований MVP выбранный вариант полностью соответствует принципам KISS и DRY.
